# 루틴 알림 구현과 검증

## v3.0 출처별 상세 연결

알림을 만들 때 실제 DB UserRoutine.source를 읽어 HERO_DAY는 MainActivity(오늘), PERSONAL은 RoutineActivity(나만의 계획)로 연결합니다. Long 루틴 ID와 날짜는 유지합니다. 화면에서 요청 ID의 실제 출처가 다르면 올바른 화면으로 다시 연결하고, 다른 출처의 편집·완료·삭제를 거부합니다. 기존 예약·권한·시각·완료 검증과 코인 트랜잭션은 유지합니다. 실제 OS 알림 수신 및 상세 연결 실행은 이번 환경에서 미실행입니다.


## 실제 동작

직접 추가하고 알림을 켠 사용자 루틴만 예약합니다. 전역 알림 설정과 Android 알림 권한이 모두 허용되어야 합니다. 반복 요일은 월요일 bit 0 ~ 일요일 bit 6으로 저장하며, 매일 같은 로컬 시각에 해당하는 **다음 한 번**을 `AlarmManager`로 예약합니다. 24시간 고정 간격으로 반복하지 않아 타임존과 DST 변화에 따라 계산할 수 있습니다.

Android 12 이상은 매번 `canScheduleExactAlarms()`를 확인합니다. 허용되면 `setExactAndAllowWhileIdle(RTC_WAKEUP)`를 사용하고, 특별 권한이 없거나 요청 중 권한이 취소되면 `setAndAllowWhileIdle`로 예약합니다. 설정 화면은 정확/대략 예약 상태와 실패를 구분합니다. 대략 알림 및 유휴 상태에서는 Android가 지연시킬 수 있으며 정확한 분 단위 전달을 보장하지 않습니다. WorkManager를 정확한 알람으로 사용하지 않습니다.

Android 13 이상에서는 `POST_NOTIFICATIONS` 런타임 권한을 별도로 요청합니다. 거절하거나 시스템에서 앱 또는 선택된 알림 채널을 차단하면 예약을 취소하며 성공으로 표시하지 않습니다. 소리 설정은 소리가 있는 기본 채널과 별도의 무음 채널 중 하나를 선택합니다. Android 설정에서 변경한 채널 설정은 사용자의 선택을 우선합니다.

알림을 누르면 인물 ID, 사용자 루틴 Long ID, 해당 날짜를 전달해 루틴 화면을 엽니다. 알림의 **완료**는 DB 트랜잭션으로 기록과 코인을 한 번 지급합니다. **5분 미루기**는 원래 날짜에만 유효하며 완료 이후에는 울리지 않습니다. 자정을 넘는 미루기는 다음 날의 루틴으로 전환하지 않습니다.

## 예약 일관성

- 루틴별 일반 예약 1개, 명시적 미루기 예약 최대 1개를 사용합니다.
- immutable PendingIntent의 data URI에 Long ID와 작업 종류를 넣어 ID 절삭·충돌·덮어쓰기를 방지합니다.
- 수정·비활성화·삭제·전체 알림 끄기·완료 시 이전 예약과 표시 중 알림을 취소 또는 교체합니다.
- 수신 시 DB의 현재 상태, 반복 요일, 시간, 타임존, 날짜, 완료 여부, 저장된 예약 토큰을 다시 검증합니다.
- 앱을 열었을 때 이미 도래했지만 Android가 아직 전달하지 않은 같은 날짜의 대략 알림은 다음 날 예약으로 덮어쓰지 않습니다.
- 루틴별 최근 32개 실천 날짜의 전달 기록을 보관해 타임존을 왕복하거나 취소 후 다시 켜도 같은 날짜의 일반 알림이 반복되지 않게 합니다. 저장량은 루틴당 최대 32개 날짜로 제한하며, 임의로 아주 오래전 시스템 날짜로 되돌리는 경우까지 무한한 중복 방지를 보장하지 않습니다.
- 같은 날짜의 일반 알림은 한 번만 표시합니다. 해당 날짜에 이미 울린 뒤 시간을 수정해도 일반 알림을 다시 지급하지 않으며 사용자가 요청한 미루기는 구분합니다.
- 수신한 예약을 먼저 소비하고 전달 상태를 저장해 중복 방송을 거부합니다. 이 방식은 중복을 막지만 저장 직후 프로세스가 죽으면 한 번의 알림이 누락될 수 있습니다. Android와 프로세스 종료 상황까지 정확히 한 번 전달을 보장한다고 주장하지 않습니다.
- `goAsync()`와 단일 작업 스레드에서 DB와 예약 작업을 수행하고 `finally`에서 수신 처리를 마칩니다.
- 부팅 완료·시간/타임존 변경·앱 업데이트·정확한 알람 권한 부여 방송 및 앱 복귀 시 예약을 복원합니다.
- Android는 정확한 알람 권한 **철회** 시 기존 정확한 예약을 삭제하고 철회 방송을 보내지 않습니다. 앱 복귀 시 다시 점검하여 대략 예약으로 복구합니다.

## 날짜 정책

기기의 현재 타임존을 기준으로 실천 날짜를 계산합니다. DST로 존재하지 않는 시각은 전환 간격만큼 앞으로 이동하고, 시각이 두 번 존재하면 GregorianCalendar의 나중 표준시 시각을 선택합니다. 날짜 자체가 없는 타임존 전환에서는 다른 요일로 해당 루틴을 옮기지 않습니다. 늦어진 일반/미루기 알림이 원래 날짜를 넘었으면 표시하지 않습니다.

## 한계와 기기 검증

강제 중지된 앱은 Android가 방송과 예약을 막을 수 있으므로 다시 앱을 열어야 합니다. 제조사 절전 정책, 알림 채널 차단, Doze의 전달 간격 제한, 권한 변경으로 전달이 늦어지거나 중단될 수 있습니다. 시스템 채널의 실제 소리, 실제 알림 전달, 재부팅과 권한 거절 동작은 Android 기기에서 확인해야 하며 JVM 테스트·APK 컴파일은 이를 증명하지 않습니다.

기기 검증 순서:
1. 루틴 추가 → 가까운 미래 시간과 반복 요일 설정 → 루틴별 알림 켜기.
2. Android 13+ 알림 권한 거절 시 차단 상태와 예약 취소 확인, 허용 후 예약 복원 확인.
3. Android 12+ 정확한 알람 권한 없이 대략 예약 안내 확인, 허용 후 정확한 예약 확인.
4. 실제 알림 클릭으로 해당 인물·루틴·날짜 열기 확인.
5. 완료 연속 누르기 → 기록과 코인 1회 지급, 알림/미루기 취소 확인.
6. 5분 미루기 → 한 번 예약, 앱에서 완료한 뒤 재알림 없는지 확인.
7. 시간·반복 요일 수정과 루틴 삭제 후 이전 알림이 울리지 않는지 확인.
8. 무음 채널 전환, 시스템 채널 차단과 해제, 앱 강제 중지 후 재실행 확인.
9. 재부팅·타임존 변경·정확한 권한 철회 후 앱 복귀 시 예약 복원 확인.

## 자동 검증 범위

알림 계산·전달 정책·의도 식별자에 대한 JVM 테스트 24개를 독립 Kotlin/JUnit 실행으로 확인했습니다(실패 0). 반복 요일, 윤년/연도 경계, 서울/UTC, DST gap/overlap, 날짜 자체가 없는 타임존 전환, 중복·완료 후 전달 방지, Long ID 충돌, 오래된 알림 버튼, 지연된 미루기 예약 유지를 포함합니다.

실제 SharedPreferences 지속성·예약 교체·취소·날짜별 전달 기록에 대한 Android 계측 테스트 8개도 추가했습니다. 계측 테스트와 실제 OS 알림 전달의 실행 여부는 최종 프로젝트 점검 보고서에 기록하며, APK 컴파일을 기기 테스트 통과로 간주하지 않습니다.
