# 위인의 하루 2.0 구현 보고서

검증일: 2026-10-13. Kotlin/XML, applicationId `com.example.test`, 기존 서명 키를 유지하고 앱 표시 이름은 **위인의 하루**, 버전은 **2.0(versionCode 2)**으로 변경했다. 기존 체크아웃을 사용했으며 시작 시 사용자 변경은 없었다.

개인 루틴은 콘텐츠 템플릿의 ID와 제목·시간을 저장한다. 콘텐츠가 나중에 편집되어도 저장된 루틴 제목/시간이 자동으로 바뀌지 않으며 완료 당시 제목과 인물은 기록에 남는다. 로그인, 외부 서버, 현금 결제는 만들지 않았다. 코인은 현금 가치가 없는 로컬 앱 포인트이다.

## 역사 자료와 이미지

세종, 이순신, 아인슈타인, 뉴턴, 다 빈치, 셰익스피어, 프랭클린, 다윈, 마리 퀴리, 나이팅게일, 마르쿠스 아우렐리우스, 소로, 프레더릭 더글러스, 존 뮤어, 제인 애덤스를 포함한다.

프랭클린 자서전의 계획표와 회고, 다윈의 메모 습관, 퀴리의 연구/여가 회고, 소로와 더글러스의 학습 기록 등을 실제 읽은 자료로 확인했다. 세종은 실록, 이순신은 난중일기를 인용하는 국사편찬위원회 자료를 사용했다. 나이팅게일은 저술의 간호 지침, 뉴턴·다 빈치는 저술의 연구/관찰 지침을 현대적으로 적용한다. 이를 모두 저자의 매일 고정 일과라고 주장하지 않는다.

셰익스피어는 개인 하루 일과를 확인하지 못해 작품 기반 창작 실천임을 명시했다. 프랭클린의 일과표는 계획이며 지키기 어려웠다는 회고도 반영했다. 세종 이미지는 동상, 이순신 이미지는 흉상이라는 점을 표시했다. 기록에 시간이 없는 항목에 시각을 지어내지 않았다. 생성 이미지는 사용하지 않았다.

- [자료별 사실·현대적 적용·원문 위치](historical-sources.md)
- [이미지별 작가·라이선스·출처](image-credits.md)
- 검토 데이터: `historical-catalog.json`, `portrait-metadata.json`
- 앱 오프라인 출처 화면: `assets/history-credits.html`

이미지 압축 파일 합계와 최대 해상도는 확인했지만, 실제 기기의 RAM·누수·프레임 성능을 프로파일링하지 않았다. 메모리 절감률을 주장하지 않는다.

## 저장 구조와 일관성

기기 내 Android SQLiteOpenHelper를 사용한다. 런타임 SQLite 버전은 Android 기기에 따라 달라지며 공유 스키마는 `assets/database/schema_v1.sql`이다. Room이나 새 백엔드 의존성을 추가하지 않았다.

루틴 FK, 인물·템플릿·날짜 UNIQUE, 완료·보상 트랜잭션, 구매 트랜잭션, 정수 CHECK 및 오버플로 검사로 중복과 부분 갱신을 막는다. SQLite TEXT에는 길이 CHECK를 사용하며 CHAR/VARCHAR 변경으로 RAM이 줄어든다고 가정하지 않았다. 조회 인덱스와 날짜별 일괄 완료 조회, 제한/오프셋 기록 조회를 적용했다.

삭제는 soft delete이다. 같은 템플릿을 다시 추가할 때 새 채택 ID를 만들지만 같은 날짜의 보상은 이전 완료 기록에 연결해 다시 지급하지 않는다. 다음 날짜의 정상 실천에는 보상을 지급한다. 기존 샘플 기록과 새 역사 템플릿은 의미가 다르므로 임의로 연결하지 않았다.

자세한 타입·제약조건·이전 정책과 테스트 한계는 [로컬 DB 문서](local-database.md)를 참고한다. 사용자 기기의 실제 앱 업데이트/프로세스 종료 후 복원은 기기 검증이 남아 있다. 미래 DB 버전은 데이터를 보존하는 명시적 마이그레이션 없이 열거나 삭제하지 않는다.

## 실제 알림과 권한

Android 13 이상 알림 권한, Android 12 이상 정확한 알람 허용을 확인한다. 정확한 권한이 없으면 대략 예약을 사용하고 지연 가능성을 표시한다. 소리/무음 채널은 별도로 생성하며 사용자가 Android 설정에서 차단한 상태를 확인한다.

Long ID를 잘라 requestCode로 쓰지 않고 종류·ID를 담은 immutable PendingIntent URI로 구분한다. 알림 발생/버튼 동작은 최신 DB 상태와 시각/타임존 설정, 발생 토큰을 다시 검증한다. 완료·삭제·중지 후 오래된 알림과 중복 방송이 코인을 재지급하지 않는다. 지연된 알림을 앱 재진입 시 다음 날 예약으로 덮어쓰지 않는다.

알림 권한 거절·예약 실패를 성공으로 표시하지 않는다. Android 강제 중지 중에는 예약/복원이 보장되지 않으며 사용자가 앱을 다시 열면 재조정한다. 정확한 권한이 있어도 기기 제조사의 절전 정책과 OS 상태에 따라 실제 수신을 보장할 수 없다. 최근 32개 civil date로 시각/타임존 왕복 중복을 제한하며 임의로 수십 일 이상 과거로 되돌리는 동작에 무제한 알림 중복 방지를 주장하지 않는다. 코인의 중복 방지는 별도 DB 제약조건으로 보호된다.

호스트 SQLite 테스트는 실제 SQL 스키마와 거래를 실행하지만 Android SQLiteOpenHelper·ContentValues·SharedPreferences 구현을 실행하는 테스트가 아니다. Android 저장소 테스트 15개, 알림 지속성 8개와 화면/기존 테스트는 별도 기기 실행이 필요하다.

## 사용자 확인 순서와 남은 검증

1. 이전 `test` 앱을 지우지 않고 새 APK를 업데이트 설치한다. 홈/기록에서 이전 데이터가 보존되는지 확인한다.
2. 인물 → 습관 → 시간·반복 요일 선택 → 내 루틴에 추가한다.
3. 루틴 상세의 설정에서 해당 알림을 켜고 앱 설정에서 알림·정확한 알람 권한을 선택한다.
4. 실제 알림 수신, 상세 진입, 완료/5분 미루기, 중복 완료 방지와 10코인 지급을 확인한다.
5. 칭호를 구매·적용하고 홈 표시와 앱 재실행 후 잔액/보유 상태를 확인한다.

현재 adb 연결 기기와 /dev/kvm이 없다. 실제 설치, 알림 수신·권한 거절·재부팅/시각 변경, 회전/실제 프로세스 재시작, 야간 대비·접근성 탐색, 메모리·프레임 프로파일링은 미검증이다. APK 빌드와 순수 로직 테스트를 이 검증의 대체로 표현하지 않는다.
