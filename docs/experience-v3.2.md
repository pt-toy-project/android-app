# v3.2 시작 경험·백업·화면 정리

## 실제 변경

첫 실행에 Google 로그인/계정 없이 시작과 3단계 사용 안내를 추가했다. 안내 완료는 기기에 저장하고 설정에서 다시 볼 수 있다. 알림의 실제 루틴 상세 링크는 안내로 가로막지 않는다. 인물 30명·240블록·510퀘스트와 기존 ID/DB 구조/코인 규칙을 유지했다.

오늘은 ‘지금 할 실천 → 실천 시작’으로 세부 체크를 열고, 같은 블록을 아래 목록에 반복하지 않는다. 관리에서는 전체 블록을 보여 준다. 목록의 근거·완료·상세를 한 행으로 모으고 큰 글꼴에서는 세로로 펼친다. 홈의 개발용 버전 부제는 설정으로 옮겼다. 설정은 내 기록·알림·도움말로 정리하고 긴 알림 진단을 상세 보기로 옮겼다.

파일 백업은 원본의 모든 테이블과 알림/소리 설정을 포함한 형식 1 / DB v3 JSON이다. 체크섬·버전·타입·크기·실제 날짜/루틴값을 검증한다. 복원은 정보 확인과 사용자의 복원 클릭 후 실행한다. 기존 데이터를 복원 전 사본으로 남기고, SQLite 외래키·CHECK·무결성·완료 기록의 인물/블록 일치 확인 아래 트랜잭션으로 복원한다. 실패 시 DB와 설정을 보존/롤백한다. 계정 선택·토큰·기기별 알람 예약 메타데이터는 백업하지 않는다. 복원 이후 알림은 현재 기기의 권한에 따라 다시 예약 요청한다.

Google 로그인은 Credential Manager + Google Identity를 사용한다. Drive 백업은 같은 선택 계정에 AuthorizationClient로 appDataFolder 권한을 요청하며 매 동작마다 재승인 상태를 확인한다. 토큰은 저장/로그/백업하지 않는다. 자동 동기화·자체 인증 서버는 구현하지 않는다. Google 표준 SDK 로그인 버튼을 사용하고 프로필 사진을 다운로드하지 않는다.

## Google 연결 제한

현재 사용자는 Google Cloud 프로젝트/OAuth 설정을 갖고 있지 않으며 환경에도 관련 관리 자격 증명이 없다. 공개 웹 클라이언트 ID가 없는 빌드는 Google 연결 준비 중으로 표시하고 성공을 흉내 내지 않는다. 실제 Google 로그인·Drive 업로드/다운로드는 미실행이다. [처음 설정하는 방법](google-account-setup.md)의 앱 등록과 실제 계정 테스트가 필요하다.
