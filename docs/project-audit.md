점검일: 2026-10-12. Kotlin/XML, 기존 namespace와 applicationId, 의존성 버전, 기존 체크아웃을 유지했다. 시작 시 사용자 변경과 AGENTS.md는 없었다. 새 DB·백엔드·보상 서버를 만들지 않았다.

## DB, 타입 및 데이터 관리

**현재 저장소에서 DB 점검 불가.** 의존성과 소스에 Room, SQLite, 서버 클라이언트, SQL, 스키마, 마이그레이션, 서버 URL이 없으며 Manifest에도 인터넷 권한이 없다. 새 로컬 저장소는 관계형 DB가 아닌 SharedPreferences이다.

따라서 CHAR/VARCHAR/TEXT, PK/FK, 인덱스, N+1, SQL 트랜잭션, 실제 DB 캐시 및 컬럼 용량을 평가하거나 변경하지 않았다. 요청된 DB 점검을 완료하려면 아래 자료가 필요하다.

- 실제 백엔드 저장소 또는 DDL·마이그레이션 파일
- DB 엔진·버전·문자셋·collation
- 주요 조회, 완료 처리, 보상 지급, 구매 처리 코드
- 비밀값을 제외한 연결 설정 및 격리된 테스트 DB 사용 방법

타입 권고는 이 자료와 실제 데이터 길이·조회 패턴을 확인한 뒤 결정해야 한다. CHAR→VARCHAR가 자동으로 RAM 절감을 의미하지 않으며, 디스크·인덱스·DB 캐시·Android 객체 메모리를 구분해야 한다. SQLite의 VARCHAR(n)은 길이를 강제하지 않으므로 필요하면 CHECK와 입력 검증이 필요하다. 현재 스키마에 대한 권고나 마이그레이션을 가정하지 않았다.

현재 로컬 데이터 설계:

- 위인은 표시 이름과 분리한 안정적인 문자열 ID를 사용한다.
- 날짜는 검증된 civil date(년·월·일)로 관리하고 키에는 ISO 날짜를 사용한다. 현재 날짜는 기기 타임존 기준이다.
- 시각은 엄격한 HH:mm 입력이며 비교할 때 분 단위 값으로 변환한다. 잘못된 날짜·시각을 임의로 보정하지 않는다.
- 완료 키는 `completed:<heroId>:<yyyy-MM-dd>`, 값은 완료된 루틴 ID의 집합이다. 다른 위인·날짜에 상태가 섞이지 않는다.
- 같은 완료 요청은 한 번만 기록한다. 저장소 인스턴스가 달라도 프로세스 내부 공유 잠금으로 read/modify/write를 직렬화한다.
- 미래 날짜와 존재하지 않는 루틴은 기록을 거부한다. 완료 여부는 불변 모델로 화면에 전달한다.
- SharedPreferences.apply는 메모리 갱신 후 디스크에 비동기 저장한다. 새 저장소 객체에서 복원하는 테스트는 실제 프로세스 강제 종료·재시작 검증과 다르다.
- 이 저장소는 로그인, 다중 사용자/프로세스, 서버 동기화, 금전·코인 거래의 원장이나 트랜잭션 보장을 제공하지 않는다. 기록 누적에 따라 XML과 메모리 적재량이 늘 수 있으므로 대규모/장기 사용은 별도의 DB 설계가 필요하다. 기록을 임의로 삭제하지 않았다.
- Android 시스템의 기존 백업 정책은 유지했다. 앱 서버에 동기화하는 기능은 없다.

날짜 선택은 savedInstanceState로 재생성 시 복원한다. 앱을 새로 실행하면 오늘을 보여주며, 완료 기록과 마지막 위인 선택은 로컬 저장소에서 다시 읽는다. 홈과 루틴의 시각 관련 표시는 전경에서 분 단위 갱신하고 백그라운드에서 타이머를 해제한다. 이미 열린 미래 날짜 상세창도 날짜가 도래하면 완료 버튼 상태를 갱신한다.

## 생명주기, 메모리 및 UI 정리

- HeroCatalog, RoutineCatalog, 순수 날짜·상태 로직, 로컬 저장소, Activity, ListAdapter 역할을 분리했다. 새 의존성은 추가하지 않았다.
- Adapter가 Dialog와 화면 전환을 직접 소유하던 구조를 Activity 콜백으로 바꾸고 상세 Dialog와 DatePicker를 화면 중지 시 해제한다. 루틴 상세는 인수와 FragmentResult를 이용해 원래 데이터 범위를 보존한다.
- 목록 갱신에 DiffUtil을 사용하고 Adapter/LayoutManager를 반복 생성하지 않는다. 누수 위험은 정적 검토 결과이며 프로파일러로 실제 누수를 측정한 것은 아니다.
- 세종 이미지 파일은 내용 변경 없이 drawable-nodpi로 이동해 불필요한 밀도 확대를 피했다. 메모리 절감량을 측정하거나 주장하지 않는다.
- API 24에서도 적용되는 여백 속성, 48dp 달력 버튼, 접근성 설명, 텍스트로 구분되는 완료 상태, 야간 색상, 시스템 바/컷아웃 Insets 처리를 적용했다.
- 거짓 진행률·사용자명·명언·보상/알림 성공 안내, 빈 파일·미사용 빈 레이아웃·색상, 광범위한 lint 억제를 정리했다.

## 남은 확인과 다음 우선순위

현재 adb devices에 기기가 없고 /dev/kvm도 없다. 기기 실행, 회전·실제 프로세스 재시작, 상태 복원, 연속 클릭 UI, 야간 대비, 접근성 탐색, 시스템 바 배치는 계측/실기기 확인이 필요하다. 완료 처리와 날짜 계산 JVM 테스트 통과를 이 UI 검증의 대체로 간주하지 않는다.

1. 격리된 Android 기기에서 15개 계측 테스트 실행 및 API 24/최신 API, 회전, 자정 경계, 재시작 확인.
2. 위인별 실제 루틴 자료와 완료 처리 UX를 확정. 현재 일정은 공통 예시이다.
3. 백엔드/DDL·엔진·버전·쿼리를 제공받아 DB 타입, 제약조건, 인덱스, 마이그레이션과 거래 일관성 검토.
4. 인증/동기화/코인·상점·실제 알림은 제품 요구사항과 데이터 계약을 정한 뒤 별도 기능 작업으로 구현.
