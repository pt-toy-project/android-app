# v3.1 서브 퀘스트 구현·검증

- 인물 추가·제외 없음: 30명 유지. 펠레와 호날두는 예시로만 다루고 추가하지 않았다.
- 기존 240블록에 고정 ID를 가진 510개 MODERN 퀘스트. 핵심 블록은 인물별 다른 행동 2~3개와 제안 분량을 제공한다.
- 목표 선택 + 기존 검색/분야 필터. 목록은 제목·진행 상태, 상세는 실제 체크 항목. 근거·출처는 접어서 제공한다.
- 아침/점심/저녁을 기상/식사/휴식의 세부 항목에 배치한다. 사용자 저장 제목·시간·요일·알림·활성화는 덮어쓰지 않는다.
- DB v3는 추가 테이블만 도입한다. 체크는 실제 채택 ID·퀘스트 ID·날짜별이며 두 출처가 독립적이다. 전체 체크와 부모 완료는 별도이고 체크 자체에 코인을 지급하지 않는다.
- 조회/체크/업그레이드/보상 보호와 인물·블록 ID 보존을 실행 검증했다. 15장 사진·벡터 아바타·이미지 크레딧·기존 history-credits.html·v1/v2 SQL은 바이트 단위로 보존했다. 이미지 증가 0 B.

## 실제 실행

필수 Gradle 4개 작업 성공: 앱 APK, JVM 104개(실패/오류/스킵 0), lint 오류 0·경고 130, 계측 테스트 APK 빌드. `python3 scripts/verify_database.py`: 21개 통과.

Robolectric/Android 35에서 실제 SQLiteOpenHelper의 v1→v3, v2→v3를 실행하고 기존 모든 테이블과 새 설치 구조를 비교했다. v2 fixture는 기존 합성 v1 파일을 v2로 변환하고 HERO_DAY 설정 행을 추가한 실제 SQLite 파일이며 사용자 데이터 추출물은 아니다.

UI에서는 실제 목표 선택창 항목 클릭과 타임라인 상세→체크박스 클릭→DB 저장을 실행했다. 체크 뒤 코인 0과 진행 상태를 확인했고, 별도로 부모 완료 및 두 출처 중복 보상을 검증했다. 200% 글꼴의 읽기 전용 세부 항목·근거 펼침을 실행했다. Native Graphics로 목록·오늘·상세 체크 화면을 렌더링했으며 PNG는 빌드 검증 산출물로만 남기고 APK에 넣지 않았다.

초기 UI 테스트의 체크박스 performClick 반환값(리스너 없으면 false) 검사를 실제 체크 상태·DB·잔액 검증으로 바로잡았다. Material의 접근성용 modal popup과 일반 popup을 구분해 실제 선택 항목을 클릭하고, 앱에서는 필터된 선택창의 위치 대신 선택 값을 사용한다. 기존 보호 조건과 테스트·lint 실행은 유지했다.

## 미실행·배포 제한

계측 테스트 50개는 빌드만 했으며 실기기 실행, TalkBack, OS 알림/재부팅, 실제 업데이트 설치, 제조사 최대 글꼴, 실기기 메모리·성능 측정은 미실행이다. 시뮬레이션 캡처를 실기기 화면이라고 주장하지 않는다.

versionCode 4 / versionName 3.1, 패키지 com.example.test. 현재 v3.0 APK와 인증서 SHA-256 bf3489b7cb1b71f6f452b1e3caea6859e29365b69a37d5d8680c536dc5f81c4c가 일치한다. 기존 v2 인증서의 개인 키는 없으므로 v2 업데이트 호환을 주장하지 않으며 기존 앱 삭제를 안내하지 않는다.

자료의 기존 미확인 상태를 유지했다. 모든 신규 세부 행동·시간·횟수는 직접 작성한 앱 제안이다. 새로운 인물·이미지·폰트·라이브러리·번역문은 추가하지 않았고, 미확인 이용조건과 개별 인물 이름 활용의 출시 전 권리 검토는 남는다. 최신 APK SHA-256과 대응 소스 커밋은 downloads/v3-build-manifest.json을 기준으로 한다.
