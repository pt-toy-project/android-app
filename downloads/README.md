휴대폰에서 다운로드한 APK를 열고 설치합니다. 설치 권한을 요청하면 해당 브라우저나 파일 앱의 앱 설치 권한을 허용한 뒤 다시 진행합니다. 저장소가 비공개인 경우 접근 권한이 있는 GitHub 계정으로 로그인해야 합니다.

기존 `test` 앱을 삭제하지 않고 새 APK를 업데이트 설치할 수 있도록 같은 패키지와 같은 서명 인증서를 유지했습니다. 기존 기록은 별도 이전 기록으로 보존하며 기존 샘플 기록에 코인을 소급 지급하지 않습니다. 실제 기기 업데이트 설치 검증은 미실행입니다.

인물 15명·출처 기반 실천 29개·실제 사진 15장, 개인 루틴 시간/반복 요일/알림 설정, 날짜별 기록, 10코인 완료 보상, 칭호 구매·홈 적용을 확인할 수 있습니다. 역사 자료와 현대적 적용을 분리했으며 기록에 없는 하루 시간표는 지어내지 않았습니다.

알림은 루틴 상세의 **시간·반복·알림 설정**에서 켜고 앱 **설정**에서 Android 알림 권한을 허용합니다. 정확한 알람 권한이 없으면 대략 예약하므로 수신이 늦어질 수 있습니다. 알림에서 완료하거나 같은 날짜 안에서 5분 미룰 수 있습니다. 강제 중지 중에는 알림을 보장하지 않으며 앱을 다시 열면 예약을 복원합니다.

서버 동기화와 실제 결제는 없습니다. 기기 테스트 44개는 컴파일만 확인했고 실제 실행은 하지 않았습니다. 빌드/단위 테스트 성공과 실제 설치·알림 수신·재부팅 검증을 구분합니다. 전체 기능·근거·제한은 [2.0 구현 보고서](../docs/implementation-v2.md)를 참고하세요.

SHA-256 파일은 [android-app-debug.apk.sha256](android-app-debug.apk.sha256)입니다. PC에서 선택적으로 검증하려면 두 파일을 같은 폴더에 내려받고 실행합니다.

```bash
sha256sum --check android-app-debug.apk.sha256
```

이 파일은 위 소스 커밋을 빌드한 스냅샷입니다. 이후 코드만 수정해도 자동으로 갱신되지 않으며 새 APK를 빌드해 함께 교체해야 합니다. 빌드 결과는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다.
